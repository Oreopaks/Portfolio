# MVP3 — RAG-ассистент по документам (с цитированием источников)

Загрузите документ -> задайте вопрос -> получите ответ **со ссылками на
конкретные фрагменты-источники**. Это ключевой отличительный демо-кейс:
не «болталка», а ассистент, который отвечает по вашей базе знаний и
показывает, откуда взял ответ.

## Что это

- **Локальные эмбеддинги** (`embedder.py`) — TF-IDF на чистом Python,
  без numpy и без внешних API. Токенизация по русским и латинским словам.
- **RAG-ядро** (`rag.py`) — чанкинг документов, индекс (чанки + векторы +
  имена документов) с персистом в `rag_index.json`, поиск по косинусной
  близости, генерация ответа через `shared.llm.chat`.
- **Веб-интерфейс + API** (`api.py`) — Flask: загрузка документа (вставка
  текста или файл `.txt` / `.md` / `.pdf`), вопрос, ответ + источники.
- Работает **полностью офлайн**: эмбеддинги локальные, LLM по умолчанию
  `mock`. Боевой LLM (GigaChat / YandexGPT) включается одной переменной
  окружения — код менять не нужно.

## API

- `POST /ingest` — `{"name","text"}` ИЛИ multipart-файл `.txt/.md/.pdf`.
  Возвращает `{"name","chunks"}`. Документы накапливаются в индексе.
- `POST /ask` — `{"query"}` -> `{"answer","sources":[{"doc","chunk","score"}]}`.
- `GET /` — встроенная HTML-страница (textarea для документа + поле вопроса).

Пример:

```bash
curl -s localhost:8080/ingest -H 'Content-Type: application/json' \
  -d '{"name":"kb.md","text":"Возврат товара возможен в течение 14 дней."}'
curl -s localhost:8080/ask -H 'Content-Type: application/json' \
  -d '{"query":"сколько дней на возврат?"}'
```

## Демо-сценарий (легенда для показа клиенту)

1. Открыть `http://localhost:8080`.
2. Загрузить готовую базу `sample_docs/company_kb.md` (правила магазина:
   возвраты, доставка, гарантия, оплата, лояльность) — вставить текст или файл.
3. Спросить «**сколько дней на возврат?**» -> ответ + подсвеченный источник
   с фразой про 14 дней.
4. Спросить «**какой гарантийный срок?**», «**бесплатная доставка от какой
   суммы?**» -> каждый ответ сопровождается ссылкой на нужный фрагмент.
5. Подменить базу на документ клиента — ассистент мгновенно отвечает по нему.

В режиме `mock` ответ детерминированный (для теста корректности retrieval);
с реальным LLM-ключом ответы становятся естественными — retrieval и
цитирование при этом те же.

## Включить реальный LLM (опционально)

В `/home/oleg/freelance-mvp/.env`:

```
LLM_PROVIDER=gigachat
GIGACHAT_AUTH_KEY=...        # или LLM_PROVIDER=yandex + YANDEX_API_KEY/FOLDER_ID
```

Код приложения не меняется — `shared.llm` сам выберет провайдера.

## Поддержка PDF (опционально)

Загрузка `.pdf` включается автоматически, если установлен `pypdf`:

```bash
.venv/bin/pip install pypdf
```

Без него `.txt`/`.md` работают как обычно, ошибки нет.

## Почему это дорого стоит (низкая конкуренция)

- **Высокая ценность, мало кто умеет делать нормально.** Большинство
  «чат-ботов» галлюцинируют. Здесь ответ привязан к документу и снабжён
  ссылкой на источник — это снимает главный страх бизнеса перед ИИ
  (выдумывание фактов) и сразу пригодно для поддержки/онбординга/юр-базы.
- **Свой документ за минуту.** Клиент видит ответы по своей базе знаний
  прямо на встрече — это продаёт само себя.
- **Локальные эмбеддинги -> нет утечки данных и нет затрат на API за поиск.**
  Можно держать всё внутри контура компании (актуально для РФ-комплаенса),
  а LLM подключить российский (GigaChat / YandexGPT) без VPN.
- **Готовый каркас под кастомизацию** (объём базы, форматы, права доступа),
  что позволяет продавать не один раз, а как услугу с поддержкой.
